# 屏幕问答 · Screen QA —— 完整解释

> 一句话：**按住热键圈住屏幕上的题 → 本机读字 → DeepSeek 多次独立作答再投票 + 交叉审核 → 答案洗好放进剪贴板，按 Ctrl+V 就能提交。**

这份文档讲清楚四件事：它是怎么串起来的、准确度是怎么提上去的、为什么没人能承诺「错误率 ≤1%」、以及考试当天怎么用它不出错。

---

## 1. 为什么中间非得有一步「读字」

DeepSeek 官方 API（`https://api.deepseek.com`，`deepseek-chat` / `deepseek-reasoner`）是**纯文本模型**：`messages` 里只能放文字，不接受图片。所以「看图答题」必须拆成两段：

```
截图（像素）  ──读字──▶  文字题目  ──思考──▶  答案文字
            本机完成              联网，DeepSeek
```

- 读字这一段：默认走 **modlens 视觉模型**（如果你装了），失败则自动降级到**Windows 自带 OCR**（`Windows.Media.Ocr`，零安装、离线、不出本机）。
- 思考这一段：只有**文字**发给 DeepSeek，截图永远不出本机。

这也解释了一个常见误解：不是「DeepSeek 看了图」，而是「本机把图变成字，DeepSeek 读字」。

## 2. 数据流（一次框选到底发生了什么）

```
 ① Ctrl+Alt+Q 框选
    └─ capture.RegionSelector：先整屏抓一张 → 铺半透明遮罩 → 拖框 → crop
       记录 bbox（给连续模式复用）

 ② 读字 reader.read_image()
    ├─ modlens（视觉模型）: node .../modlens/dist/main.js -i 图 -o out.json
    │    成功 → result.ocr.full_text / layout.regions[].text
    │    失败（例如沙箱不允许 spawn）→ 把失败原因记进 warnings，继续
    └─ winocr（本机 OCR）: psocr.py → powershell psocr.ps1
         high 档并行跑 3 个候选：原图 / 放大锐化 / 深浅反色(+低对比度二值化)
         每个候选各自 text_score() 打分 → 取最高分那份文字

 ③ 分题 questions.split_questions()
    「Question 3. / 3) / 第3题 / （3）」等编号切分；切不动就整段当一题

 ④ 作答 solver.Solver.solve()
    ├─ 3 路**并行**独立采样（temperature 0.7）→ 各自给出「## 推理 / ## 最终答案 / ## 填入答案」
    ├─ 归一化 + 多数投票 → 得票最高者
    ├─ 票数不齐 → 自动追加 2 路并行采样再投（escalate）
    ├─ 交叉审核：把题目 + 几个候选一起给模型，让它自己判哪个对
    └─ 置信度分级：全一致=🟢高 / 有分歧或改判=🟡中 / 全失败或强分歧=🔴存疑

 ⑤ 清洗 solver.clean_fill()
    x = 5 → 5 ；２，３ → 2, 3 ；$64 → 64 ；去掉句末句点；3/5、(2, 3)、x > 3 原样保留

 ⑥ 落地
    ├─ 答案卡显示大字号答案 + 置信度 chip + 「第 9/12 题」
    ├─ 自动复制到剪贴板（fill 优先于 answer）
    ├─ 焦点还给原窗口（AttachThreadInput + SetForegroundWindow）
    └─ 写 history/YYYYmmdd-HHMMSS.md + cache.json（同题秒出）
```

## 4. 准确度是怎么一点点提上去的（都有实测数字）

| 机制 | 为什么有用 | 实测 |
| --- | --- | --- |
| **高精度 OCR 多候选** | OCR 的错是「视角相关」的：原图认不出 `标价`，放大锐化后认得出；深色主题下反色后能救回整行 | 中文题 74.0 → 75.0 分；深色小字 62.0 → 65.5 分；浅灰字 18.0 → 35.0 分 |
| **低对比度二值化** | 浅灰字/截图发灰时，Otsu 二值化能把字从背景里「抠」出来 | 浅灰题原本丢整行提示，二值化后 `B. x = 4` 回来了 |
| **候选并行**（不是串行） | 3 个候选分别起进程，墙钟时间 = 最慢那个而不是三个相加 | 1.44 秒 → 0.61 秒 |
| **多路独立采样 + 投票** | 单次输出的错误是随机的；独立多次后错答案不容易凑出多数 | 三道测试题三次采样全一致 |
| **分歧追加采样** | 票数不齐说明这题本来就摇摆，多问两路再投 | 两空题从 3 票分歧 → 6 票收敛 |
| **交叉审核** | 让模型在「看得到全部候选」的位置做裁决，比单路自说自话稳 | 审核改判时置信度会降 🟡，不装高 |
| **答案清洗** | MyMathLab 的 answer box 只认裸值，`x = 5` 粘进去算错 | `x = 5 → 5`、`２，３ → 2, 3` |
| **题号 / 同题去重** | 连续模式下 OCR 有噪声会误判「换题了」，白花钱 | 靠 `第 9/12 题` 判重，比纯文字比对稳 |
| **框歪了直接拦** | 小于 12 个字的识别结果一定是废的，问模型只会得到幻觉 | 0.3 秒内提示重框，不花一次调用 |

诚实的地方：这些机制把**常见题型**的正确率拉到很高（本机测试题连续多次全对），但**没有任何组合能证明「错误率 ≤1%」**——见下一节。

## 5. 为什么「错误率 ≤1%」是不可能承诺的

1. **两段串联，误差相乘**。识别错一个字（例如把 `x²` 读成 `x2`、把 `−5` 读成 `一5`），模型再聪明也只能基于错题干作答。要让整链 ≤1%，识别和推理各自的错误率都得远小于 1%。
2. **大模型输出不是确定函数**。同一个题、同一温度，两次采样可能给出不同推理路径；「正确率」只能在**具体题库**上统计，不能作为一个全局参数承诺。
3. **题目分布无穷**。证明题、几何作图、多空填空、带图的统计题、Canvas 里的 LaTeX 渲染……每一类的失败方式都不一样。
4. **可验证性差**。要统计"≤1%"，得有一份带标准答案的、与你考试同分布的题库，跑几百上千题——这件事没人能替你预先做完。

所以程序给的是**可操作的东西**，不是一句口号：

- 🟢 **高**：多路一致 + 审核通过 → 可以按这个交；
- 🟡 **中**：有分歧或被改判 / 极速模式单次问 → 建议点「重算」或自己核一眼；
- 🔴 **存疑**：全失败、强分歧、或识别质量差 → 不要当确定答案。

一句话：**它把「猜」变成「有依据的猜，并且告诉你有多大把握」**，但不假装自己是 100%。

## 6. 速度账本（2560×1600，真实实测）

| 阶段 | 常规 | 极速 |
| --- | --- | --- |
| 截图 | ~0.15s | ~0.15s |
| 读字（high 档 3 候选并行） | 0.8–1.0s | 0.8–1.0s |
| 3 路并行采样 | ~1.4s | 0.7s（1 路） |
| R1 复核（🟡/🔴 时） | 换 `deepseek-reasoner` 独立重解一次；改判则采用并把置信度定为 🟡，一致则把"存疑"升到"中"。代价 10–40 秒，只在不确定时触发 |
| 交叉审核 | ~1.4s | 不做 |
| **合计（新题）** | **3.9–4.5s** | **2.4s** |
| 同题再来（缓存） | 1.2s | 1.4s |
| 重算（跳过缓存） | 3.6s | — |

一屏 3 题分别作答约 12 秒（每题都走完整投票 + 审核）。

## 7. 考试当天怎么用（MyMathLab / Canvas 一小题一作答）

MyMathLab 的特点是**一小题一提交**，所以流程要贴着它走：

1. 双击 `启动.bat`（窗口跑到右下角，不挡题目）；
2. 题目加载完，按 `Ctrl+Alt+Q`，框住**这一小题的题干 + 选项 + 输入框**（框大一点没坏处，但别把浏览器地址栏框进去）；
3. 等卡片出答案（常规 4 秒级）——答案已经自动复制；
4. 点进 Pearson 的 answer box → `Ctrl+V` → `Enter`（焦点已自动还给你原来那个窗口）；
5. 多空题：先点 `空1·…` 复制第一个空，粘完再点 `空2·…`；
6. 显示 🟡/🔴 或你觉得不对 → 点「重算」，或改回常规模式再算一次。

三个坑：

- **别在 MyMathLab 一小题页面上开连续截图**：它每 3 秒抓一次，会一直重算同一屏，费额度还刷屏；
- **别让题目窗口被别的窗口挡住**：OCR 读到的是「最上层那一层像素」，挡住就是别人的字；
- **fill 与 answer 的区别**：`answer` 是给人看的完整结论（含 `x =`），`fill` 是专门给输入框的裸值。复制优先 `fill`。

## 8. 常见故障与处置

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 详情里出现 `⚠ modlens 不可用（…spawn EPERM…）` | 当前进程不允许启动子进程（沙箱/受限环境） | 自动降级本地 OCR，功能不受影响；想用视觉模型就自己双击启动，别在受限终端里跑 |
| 状态栏 `只识别到 N 个字` | 框歪了/框到空白/题目被遮挡 | 重框大一点，或 `Ctrl+Alt+W` 整屏 |
| `❌ 调用 DeepSeek 失败：401` | Key 无效/填错 | 设置里重填（platform.deepseek.com → API keys） |
| `402` / `429` | 余额不足 / 触发限流 | 换 Key 或等一会；采样数与审核都会增加调用次数 |
| 窗口跑到屏幕外/被最小化 | 外部（Win+D、切桌面）把它最小化 | 程序会自动贴回右下角；出答案时也会自动现身 |
| 答案框里出现 `$`、全角逗号 | 模型输出格式 | 已经自动清洗；若仍出现，看 `fill` 那一行 |

## 9. 隐私与安全

- **只发文字**：截图只在本机被 OCR，网络请求里只有识别出的题干文字。
- **Key 只在本地**：`config.json` 在 `.gitignore` 里，不会被提交；也可以用环境变量 `DEEPSEEK_API_KEY`。
- **历史记录**：`history/*.md`、`cache.json` 都在本地程序目录，`.gitignore` 已排除。
- **Key 泄露怎么办**：去 platform.deepseek.com 撤销重发一个，改本地 `config.json` 即可（代码里没有任何硬编码 Key）。
- **本程序的定位**：它是"辅助读题 + 复核"的工具，不替你点提交按钮；用它做的每个决定仍然是你自己的决定。

## v2.8：OCR 不可靠时自动改用剪贴板文字

Windows 本地 OCR 对"整行只有符号/极短表达式"容忍度很低（回归 30 条里 3 条失败全是它：
`sqrt(2x+1)=5` 被读成 `sqrt()x + 1 ) = 5`、`(x^2-9)/(x-3)` 与 `C(5,2)` 整行消失）。v2.8 做了三件事：

1. **`.risk()` 判风险**：识别完后立刻判定 OCR 是否可疑 —— 空括号（系数被吞）、
   题面一个数字/符号都没有（整行被丢）、`sqrt(` 后面没有内容（根号空了）。
2. **自动换源**：可疑时读剪贴板文字；**只有数字有交集**（说明剪贴板和题面是同一道题）才替换，
   避免把上一次复制的东西当成这道题。替换处会在日志里明说：
   `OCR 不可靠（读到了空括号（系数可能被吞））→ 已改用剪贴板里的文字作答（29 字）`
3. **换成"文字作答"就没 OCR 了**：这一步等价于手动按 `Ctrl+Alt+T`，只是自动触发。

设置里新增勾选 **「OCR 不可靠时用剪贴板文字」**（默认开）。想关掉就关，回归测试不受影响。

实测（`cases/c02_radical.png`，剪贴板先放下正确题干）：

```
识别中（winocr → modlens）… 本地 OCR 够用（质量 49），跳过视觉模型
OCR 不可靠（读到了空括号（系数可能被吞））→ 已改用剪贴板里的文字作答（29 字）
【最终答案】x = 12      【填入答案】12      【代入验算】把 x=12 代回去两边相等
```

顺带修了验算的两个真 bug（同一轮发现）：
- `_ALLOWED` 原来只允许 `0-9x+-*/^().`，`sqrt(...)` 直接被判为非法 → 根号题永远 skip；
  现在允许白名单函数名（sqrt/sin/cos/tan/log/ln/exp/abs/pi），其它字母仍拒绝。
- `Solve for x. 9x + 6` 会把 `x.` 当成表达式的一部分 → 新增 `_drop_clause()` 先切掉指令前缀。

现在验算对 `sqrt(2x+1)=5` 也有效：`x = 12 → ok`、`x = 24 → fail（左边 7 ≠ 右边 5）`。

## 回归结果：30 条已知答案（2026-11-21，真实 API，关缓存）

```
正确 27/30 = 90% · 总耗时 124.4s · 平均 4.1s/题 · 69641 tokens · 约 ¥0.1393
其中受本地 OCR 限制：3 条（纯符号行整行丢失 / 系数被吞）
在能读到的题面上：27/27 = 100%
```

覆盖题型：一元/二次方程、分数系数、比例、根式、不等式、指数、对数、方程组、化简、
组合数、百分比、折扣、路程、平均数、增长率、函数值、斜率、负数解、分式方程、单题意选择题。

三条失败全部不是"模型算错"，而是 **Windows 本地 OCR 把整行丢掉了**：

| 用例 | 题面 | OCR 实际读到 | 结果 |
|---|---|---|---|
| `c02_radical` | `sqrt(2x + 1) = 5` | `sqrt()x + 1 ) = 5` | 系数 2 被吞 → 模型按 `sqrt(x+1)=5` 解出 24 |
| `c10_simplify` | `(x^2 - 9) / (x - 3)` | 整行消失 | 模型回"题目不完整" |
| `c18_comb` | `C(5, 2)` | 整行消失 | 模型回"缺少组合数" |

已实测确认：这不是分辨率问题（x2/x3 放大、锐化、加白边都试过，仍丢）。
Windows OCR 对"整行只有符号/极短表达式"的容忍度很低，只要前面有一个英文词就正常
（`Simplify: (x^2 - 9)/(x - 3)` 能读成 `Simplify: （ × ^ 2 一 9 ） / （ × 一 3 ）`）。

**应对（已内置）**：
1. 框选时**把上一行题干一起框进去**，别只框那个表达式；
2. 纯符号题用 `Ctrl+Alt+T` 从网页复制题干文字直接作答（完全绕过 OCR）；
3. 你在自己环境里若装了视觉模型（设置里「视觉自检」✅），这类整行丢失可能被视觉模型救回来 —— 本机沙箱里视觉不可用，所以这一层没测到。

`python tools/regress.py` 可随时复现上面这张表；`--fast` 看极速档、`--samples N` 改采样。

## 十三、v2.9：重试、稳定性、热身

**1) 一键重试**：`App.last_job` 记住这次是"图片"还是"文字"（以及具体值），失败分支调 `_enable_retry()` 把 `b_redo` 文案改成「重试」；`redo()` 变成分派器——`_failed` 时走 `retry()`（同图/同文重跑），否则走"跳过缓存重算"。取舍：不自动重试（错误可能是 Key 欠费或网络，自动重跑只会多花钱、还掩盖原因），只把"再试一次"变成一次点击。

**2) `regress --repeat N`**：每条用例跑 N 次，`ok` 定义为 `hits == repeat`（N 次全对才算稳），部分成功标 ⚠ 并单列在"稳定性"里。为什么需要：模型 temperature 不为 0，同一张图偶尔会给出不同答案——单跑一次的 90% 是"平均"，N 次全对的 90% 才是"上考场不会翻车"。

**3) 考前热身 `warmup()`**：把散落在各处的自检串成一条链——Key 格式、`/user/balance` 余额、`psocr.available()`、`reader.backend_status()`、`hk.bound` 实际键位，然后用 `cases/c01_frac.png`、`cases/c04_ineq.png` 各跑一次真实作答（强制 `samples=1`、关验算/缓存/多题/双模型/朗读/自动复制，约 0.01 元）。结果通过 `self.q` 队列回主线程（**线程里不碰 Tk**），写详情框 + 弹窗。

**顺手修的真问题**：`check_update_async()` 原来在 worker 线程里 `self.root.after(0, show)`——没有 mainloop 的场景（脚本化测试）会抛 `RuntimeError: main thread is not in main loop`，属于隐患；改成 worker 只 `q.put(("update", info))`，由 `_poll` 在主线程处理。

## 十四、v2.10：自适应 / 流式 / 模糊缓存 / 双读校验

**1) 自适应采样**（`solver.Solver(adaptive=True)`）：`solve()` 先 `_collect(messages, 1)`，取出答案与 `fill`，调 `verify.verify()` 代回原式；`status == "ok"` 就把 `res.adaptive = True` 并跳过剩余样本，否则再补 `samples - 1` 次。要点：
- 只有"能验算且验算通过"才省 —— 选择题/证明题 `verify` 返回 `skip`，照样问满；
- 自适应通过时**跳过双模型互检**（已有一个独立信号，再花 10–40 秒不值）；
- `warnings` 里写明"省下 N 次调用"，不让用户以为程序偷偷降级。
实测：`9x+6=60` → `calls=2`（1 次作答 + 1 次交叉审核）、**1.83s**、`check=ok`。

**2) 流式**：`DeepSeekClient.chat(..., stream_cb=...)` 走 SSE（`data:` 行 + `[DONE]`），逐块回调；`Solver._collect` **只让第一份样本走流式**（并发样本一起流会把界面刷乱，且收益重复）；app 侧 `_on_stream()` 把增量屯进 `_stream_buf`，每 ~120 字或遇到 `## 最终答案` 才重绘一次详情框（避免每块都重排）。

**3) 模糊缓存**：`_fuzzy_sig(text)` = `sha1(题号/总题数 | 数字集合 | 长度档位)`；精确 key 未命中时 `find_fuzzy()` 遍历缓存条目，**签名相同且归一化文本相似度 ≥0.93** 才算命中。为什么不用纯相似度：两道不同的题（如 9x=54 和 9x=45）文字很像但数字不同，纯相似度会串题。

**4) 双读交叉校验**：`reader.cross_check_text()` 在 OCR 短路口之后额外跑一次视觉模型，`_ratio()` 用 `difflib` 比对归一化文本；`<0.55` 才警告并列出两版原文（正常题不吵），视觉版本明显更长（>1.15×）时采用视觉文本——因为"少字"往往就是被吞掉的符号或整行。视觉不可用时静默跳过，不拖慢主链路。

**5) 超时降级**：`_watch()` 超时后置 `_slow_hint=True`；`_current_cfg()` 下次被调用时把 `samples` 压到 1、`escalate` 关掉，并在日志里说明。**不取消正在跑的线程**（中途杀线程容易写坏缓存），只是下一题更快。

**6) 安装更新**：`extras.apply_update(src=_update, dest=程序目录, keep=("config.json",...))` 只复制覆盖、不删除旧文件——更新失败也不会把程序弄成半坏；`history/`、`config.json` 显式保留。

## 十六、v2.15 的"融合"：向朋友的项目学什么、不学什么

参照对象：[SpellCardHomework](https://github.com/Jerry9335/SpellCardHomework)（MIT，东方风格截屏识题工具）。

### 学过来的（按其"思考方式"重写）

| 它的做法 | 我们的实现 | 为什么值得学 |
|---|---|---|
| LaTeX → 可读符号渲染 | `latexfmt.py`：`\frac{a}{b}`→`a/b`、`\sqrt{x}`→`√(x)`、上下标→Unicode | 模型常吐 LaTeX，直接看不友好；渲染后同时用于「复制LaTeX」的反向检查 |
| 英文题自动翻译 | `prompts.TRANSLATE_SYSTEM` + `run_pipeline` 内一次 `temperature=0` 调用 | 英文题意靠猜是主要失分点；多花约 ¥0.001/题 |
| 摘录可改 → 改完重算 | 题面条 `ex_text`（可编辑）+「用这段重算」 | OCR 错一个字符就全盘错；让用户改一行比重框一次快得多 |
| 香火钱账本 | `ledger.py`：30 天柱状图 + 按模型 + CSV | 花钱透明，才敢在考试里放心用 |
| 三栏工作流（摘录/翻译/答案） | 竖向"题面条 + 答案卡 + 推理" | 窄窗（490px）放不下三栏，改成竖向顺序，信息层级一样 |
| 启动横幅 / splash | `assets/banner.png`（自绘）+ `show_splash()` | 观感，且不引入版权素材 |

### 没有学（以及理由）

- **CDP 全自动网页答题 / 自动交卷**：需要 websocket 依赖，且跨过"辅助作答"到"代交作业"的边界。我们保留 `自动粘贴 + 可选回车`，最后一步由人确认。
- **Ed25519 一机一码 / 激活码**：本项目 MIT 免费，不加授权门。
- **立绘、美术素材**：版权不明，改用纯 PIL 自绘渐变横幅。

### 融合后的完整性

两边的优点现在是互补的：它的"读题呈现"（渲染/翻译/可改）解决**输入**，我们的"代入验算 / 双模型互检 / 置信度分级"解决**输出可信度**；它记账，我们离线回归（0 元验证）。一条链路上，输入与验证都不再是黑箱。

## 十七、v2.16 排版：为什么改成三页

朋友的界面是"顶栏一排动作 + 三栏内容"，观感很强，但那是 1300px 宽的窗口。我们常驻右下角只有 490px：

- 三栏放不下 → 改成**三页**（作答 / 工具 / 记录），一页只显示一组按钮；
- 好处不只是好看：把 13 个按钮塞两行时，任何新增功能都会挤爆（v2.13 就出现过"题面"只露出一个字）。分页后每页有固定容量，新增功能只需归到某页；
- 窗口高度 983 → **833**，展开题面时才临时变高（`min(base+150, 屏高-90)`），收起就还原。

趣味点只加"有信息量"的那种：`🎯 一击命中`（说明省了 2 次调用）、`🤝 双模型一致`、`⚡ 缓存`、`¥0.0025`——不显示无意义的动画。

## 十八、v2.17：账号、自由窗口、主题与多服务商

### 为什么是"本机账号"而不是云账号

这个程序的定位是**只在本机跑、只把文字发给模型**。要做注册登录，最自洽的形态就是本机账号：

- 用途：多人共用一台电脑时隔离数据（各自的作答记录/错题本/缓存/历史/API Key）；
- 存储：`users.json` 存 `salt + PBKDF2-SHA256(pw, salt, 120000)`，`config.activate_profile()` 把数据目录切到 `data/<用户名>/`；
- 代价：换电脑不能同步、忘密码只能删 `users.json` 重置（README 里写明了）；
- 没做的：在线注册、找回密码、多设备同步——那需要一个后端，与"零服务器"直接冲突。

### 自由窗口

原来写死"贴右下角"是因为它是个常驻小工具。但 1300px 宽的大屏上，很多人希望它像普通窗口一样拖动/放大：

- `cfg["dock"] = "corner" | "free"`；free 时 `resizable(True, True)`，关窗时把 `geometry()` 存进 `cfg["win_size"]`；
- 贴角仍保留自动吸附（`snap_bottom_right` 用 `SetWindowPos` 校正外框，`<Map>` 事件在恢复时重贴）；
- `_on_map` 只在 corner 模式重贴，free 模式不抢用户摆好的位置。

### 主题色与系统强调色的优先级

坑过一次：`apply_accent("sakura")` 之后又被 `apply_system_accent()` 覆盖成系统蓝。现在的规则是——

1. `accent == "auto"` 且 `follow_accent` 为真 → 用 Windows 强调色；
2. 选了预设（blue/sakura/mint/amber）→ **忽略系统色**；
3. `Pill` 的 primary 按钮在构造时读 `UI["accent"]`，所以换色对已存在的按钮也生效（代价是运行中换色要重开窗口）。

### 多服务商

`config.PROVIDERS` 只是六组 `(base_url, 推荐模型)`：DeepSeek / OpenAI / 智谱 GLM / 通义千问 / OpenRouter / Ollama 本地。因为大家都在兼容 OpenAI 的 `/chat/completions`，所以换服务商只是换地址与模型名，`deepseek_api.DeepSeekClient` 不用改。R1 复核与视觉模型仍然只在 DeepSeek 上验证过，别在考试当天第一次试新服务商。

## 十九、云端模式：能上云的三件事与不能上云的那一件事

截图必须发生在你自己的电脑上——**云服务器看不到你的屏幕**。所以"上云"只能是这三层：

| 层 | 服务器做什么 | 客户端变化 |
|---|---|---|
| 模型代理 | 持 Key、拼请求、按账号限额、记 token | 只需令牌，本机不填 Key |
| 账号与同步 | 注册/登录、记录增量上传/下载 | 换台电脑能接着看历史 |
| 网页版 | 粘贴文字或传图 → OCR → 解题 | 手机/浏览器可用 |

实现上刻意选**纯标准库**（`http.server` + `sqlite3` + `urllib`），因为：

- 1C1G 的机器 `pip install fastapi uvicorn` 也能跑，但启动内存和依赖升级是额外负担；
- 部署只要 `python app.py`，或 `docker compose up -d`；
- 流式（SSE）自己转发 30 行就够，不必引 SDK。

**代理怎么劫持客户端**：`deepseek_api.set_cloud(base, token)` 设置后，`DeepSeekClient.__init__` 把 `base_url` 改成 `base + "/api/proxy"`、`api_key` 改成令牌——所有调用点（投票、R1 复核、翻译、判卷、练一练）自动走代理，不用改业务代码。
